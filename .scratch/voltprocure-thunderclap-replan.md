# VoltProcure Replan — Thunderclap-First Demo for Laravolt v7.0.0-beta.3

Release anchor: `laravolt/laravolt` **v7.0.0-beta.3**
Release URL: https://github.com/laravolt/laravolt/releases/tag/v7.0.0-beta.3

This replaces the earlier hand-built MVP plan. The demo should now prove that **Thunderclap is the meta feature of Laravolt v7**: schema-driven modules generated into a consistent Laravolt UI, then extended into real business workflows.

## 1. New thesis

VoltProcure should demonstrate this path:

```txt
Database schema → Thunderclap generated modules → reviewable Laravolt code → business actions/workflows → tests/docs → deployable demo
```

The article/demo should not start with hand-coded CRUD. It should show Thunderclap creating the first working surfaces, then show how teams customize those generated modules into a real procurement/inventory workflow.

## 2. What changed after beta.3

`v7.0.0-beta.3` includes the Thunderclap hardening needed for the demo:

- existing model enhancement return type fixed
- existing model enhancement now supports:
  - Suitable traits
  - searchable columns
  - `protected $guarded = [];` when no mass-assignment policy exists
- `laravolt:clap` now prints explicit registration steps for generated modules:
  - Composer PSR-4 `Modules\\ => modules/`
  - provider registration in `bootstrap/providers.php`
  - `composer dump-autoload`
  - `php artisan optimize:clear`

## 3. Demo architecture

### Generated by Thunderclap

1. `Department`
2. `Item`
3. `Supplier`
4. `PurchaseRequest`
5. `PurchaseOrder`
6. `ReceivingNote`

- Generate base `PurchaseRequest`, `PurchaseOrder`, `ReceivingNote`, `InventoryBalance`, `InventoryMovement` next if time allows.
- For complex line-item forms, keep generated CRUD as base admin/evidence screens, then add explicit workflow pages/actions.

Keep business flow explicit:

- `SubmitPurchaseRequestAction`

This is the article point: Thunderclap gets you reliable CRUD structure; Laravolt conventions let you extend it into workflow software.

## 4. Fresh implementation strategy

Prefer a clean rewrite branch/repo state over patching the earlier hand-built VoltProcure UI.

Current VoltProcure has useful code, but its index pages were hand-built. For the article, replace the manual CRUD surfaces with Thunderclap-generated modules.

### Step A — baseline app

Use beta.3 explicitly:

```bash
composer create-project laravel/laravel voltprocure
cd voltprocure
composer require laravolt/laravolt:v7.0.0-beta.3 -W
php artisan laravolt:install
php artisan migrate:fresh
php artisan laravolt:admin "Admin" admin@example.test password --no-verify
npm install
npm run build
```

If using the existing repo, update dependency to beta.3 and reset/rebuild carefully.

### Step B — define schema before generation

Create realistic migrations first. Minimum schema for first article/demo:

- `departments`: `code`, `name`, `manager_user_id`, `is_active`
- `items`: `sku`, `name`, `description`, `unit`, `category`, `reorder_point`, `standard_cost`, `is_active`
- `suppliers`: `code`, `name`, `contact_name`, `email`, `phone`, `address`, `payment_terms`, `is_active`

Then migrate:

```bash
php artisan migrate:fresh
```

### Step C — generate modules with Thunderclap

For existing app models:

```bash
php artisan laravolt:models --table=items
php artisan laravolt:clap --table=items --module=Item --use-existing-models --force
php artisan laravolt:clap --table=suppliers --module=Supplier --use-existing-models --force
php artisan laravolt:clap --table=departments --module=Department --use-existing-models --force
```

Register generated modules as printed by the command:

1. Ensure `composer.json` has:

```json
"Modules\\": "modules/"
```

2. Register providers in `bootstrap/providers.php`:

```php
Modules\Item\ItemServiceProvider::class,
Modules\Supplier\SupplierServiceProvider::class,
Modules\Department\DepartmentServiceProvider::class,
```

3. Refresh:

```bash
composer dump-autoload
php artisan optimize:clear
```

### Step D — validate generated modules

Run:

```bash
php artisan route:list | grep modules
php -d memory_limit=512M ./vendor/bin/pest modules/Item/Tests/ItemTest.php --no-coverage --colors=never
php -d memory_limit=512M ./vendor/bin/pest modules/Supplier/Tests/SupplierTest.php --no-coverage --colors=never
php -d memory_limit=512M ./vendor/bin/pest modules/Department/Tests/DepartmentTest.php --no-coverage --colors=never
npm run build
```

### Step E — extend into workflow

After generated CRUD passes:

- Add purchase request submission action.
- Add approval inbox/action.
- Add PO creation/issue action.
- Add receiving/posting action.
- Add inventory movement evidence.
- Add tests around actions and permissions.

## 7. Definition of done for the revised MVP

The MVP is ready for article/demo when:

- App uses `laravolt/laravolt:v7.0.0-beta.3`.
- At least Item/Supplier/Department CRUD modules are generated by Thunderclap.
- Generated modules are registered and their tests pass.
- Tables use `Laravolt\Ui\TableView`/Suitable from generated modules, not local raw table partials.
- Business workflow actions are added on top of generated modules.
- Feature tests cover request → approval → PO → receiving → inventory movement.
- README/DOCKER docs explain local and container startup.
- Demo docs include `docs/ai-context.md` and task recipes.
